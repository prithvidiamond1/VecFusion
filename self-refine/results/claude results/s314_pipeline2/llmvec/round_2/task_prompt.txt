        Tester feedback:
        The errors all stem from the same root cause: in Clang, comparing GCC-style `__attribute__((vector_size))` vectors with `>` returns an integer mask vector, which cannot be used as the condition of a ternary `?:` operator.

- **Fix**: Replace all ternary-based vector max expressions like `vmax0 = v0 > vmax0 ? v0 : vmax0;` with the `__builtin_elementwise_max` intrinsic or use explicit masking. The simplest portable fix is to use `__builtin_elementwise_max(v0, vmax0)` for each comparison, e.g.:
  ```c
  vmax0 = __builtin_elementwise_max(v0, vmax0);
  vmax1 = __builtin_elementwise_max(v1, vmax1);
  vmax2 = __builtin_elementwise_max(v2, vmax2);
  vmax3 = __builtin_elementwise_max(v3, vmax3);
  ```
  Apply this same fix to all 8 occurrences of the ternary vector max pattern (inside both loops and the merge section).

- **Alternative fix** if `__builtin_elementwise_max` is unavailable: use explicit mask selection:
  ```c
  typedef int int4 __attribute__((vector_size(16)));
  int4 mask = (int4)(v0 > vmax0);
  vmax0 = (float4)((mask & (int4)v0) | (~mask & (int4)vmax0));
  ```
  but `__builtin_elementwise_max` is cleaner and available in Clang 15+.
