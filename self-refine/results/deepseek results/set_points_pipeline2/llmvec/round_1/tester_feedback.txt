Looking at the failure: exit code -6 (abort/assertion) with "Mismatch in parameter src on trial 0 at index 0".

The issue is that `src[0]` is being set to `srcStart`, but the original algorithm likely doesn't set `src[0]` — or the `src` array indexing is off. More critically:

- The original code computes `srcDelta` as `divs[i] - src[i]` where `src[i]` tracks the *previous* div value, not the accumulated `src` array. The `src` array in the original is likely 1-indexed differently, or `src[0]` should not be written at all (it's an input, not output), or the function writes only `src[1..divCount+1]`.

- Looking more carefully: `src[0] = srcStart` overwrites `src[0]` which the caller already set (or expects unchanged). The mismatch is at index 0, meaning `src[0]` is being corrupted.

- The `srcDelta` computation uses `src[i+1] - src[i]` but `src[i]` for i=0 is `srcStart` (written by us), while the original likely computes deltas as `divs[i] - prev` where `prev` starts at `srcStart` without writing to `src[0]`.

- The original algorithm probably writes only to `src[1]` through `src[divCount+1]`, not `src[0]`.

**Fixes needed:**

- Remove `src[0] = srcStart;` — do not write to `src[0]`, it's an input.
- Remove `dst[0] = dstStart;` similarly if `dst[0]` is also an input (but the mismatch is only on `src`, so check `dst[0]` too).
- Recompute `srcDelta` using `divs[i] - (i == 0 ? srcStart : divs[i-1])` instead of `src[i+1] - src[i]`, since `src[0]` must not be written.
- Keep `src[i+1] = divs[i]` assignments (indices 1..divCount) and `src[divCount+1] = srcEnd` — those are the actual outputs.
- The delta for index `i` should be: `int prev = (i == 0) ? srcStart : divs[i-1]; int srcDelta = divs[i] - prev;`
- Apply this fix in both the vectorized loop and the scalar remainder, and in both `use_normal` and `else` branches.
- Also verify `dst[0] = dstStart` — if `dst[0]` is also pre-set by caller, remove that write too (but since only `src` mismatch is reported, `dst[0]` may be okay to write).
