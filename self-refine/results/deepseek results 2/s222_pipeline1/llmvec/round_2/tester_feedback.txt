The issue is that the `a[]` loop adds `bc` then subtracts `bc`, making it a no-op — but the original `s222` kernel is:

```
a[i] += b[i]*c[i];
```
followed by a second loop:
```
a[i] -= b[i]*c[i];
```

These two loops run **sequentially over the full array**, not interleaved per element. Because the vectorized code does `+= bc` then `-= bc` for the **same element in the same iteration**, it cancels out and leaves `a[]` unchanged. The original does all additions first, then all subtractions — which also cancels, but only if `b` and `c` haven't changed. The net effect on `a[]` should indeed be zero, but the `e[]` recurrence result depends on the **number of outer iterations** being `iterations/2` vs `iterations`.

- **Root cause**: The outer loop runs `iterations/2` times but the reference likely runs `iterations` times. Change `iterations/2` to `iterations` (the `/2` is incorrect for this kernel).
- The `a[]` add-then-subtract per element is logically correct (net zero effect on `a`), so that part is fine.
- The `e[i] = e[i-1] * e[i-1]` recurrence is correct and must stay scalar.
- Fix: replace `nl < iterations/2` with `nl < iterations` in the outer loop condition.
