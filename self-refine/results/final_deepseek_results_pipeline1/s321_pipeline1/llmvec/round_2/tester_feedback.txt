The vectorizer candidate has a **semantic correctness bug** in the vectorized loop body.

- **Recurrence dependency broken**: The original scalar recurrence `a[i] += a[i-1] * b[i]` requires each iteration's `a[i]` to be computed *before* it is used as `a[i-1]` in the next iteration. The vectorized code loads all `a_prev` values from `a[i-1..i+2]` *before* any `a_curr` is written, so the later elements in the vector use stale `a` values instead of the just-computed ones.
- **Fix**: The vectorized loop cannot safely process this backward recurrence in parallel. Either:
  - Remove the vectorized loop entirely and keep only the scalar loop, or
  - Restructure to a prefix-sum-like approach (e.g., scan) that respects the dependency, or
  - Use a smaller vector width (e.g., 2) with manual dependency chaining between halves.
- **Trip count / bounds**: The loop bounds `i + 3 < LEN_1D` and the scalar-first-element handling are correct for the structure, but the vector body itself is unsound for this recurrence pattern.
