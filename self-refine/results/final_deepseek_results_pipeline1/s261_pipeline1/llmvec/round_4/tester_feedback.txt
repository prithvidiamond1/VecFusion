The vectorizer candidate has a **correctness bug** in the vectorized main loop:

- **Incorrect vector load offset for `c_prev`**: The vector load `*(float32_t*)(c + i - 1)` loads 4 elements starting at `c[i-1]`, which includes `c[i-1], c[i], c[i+1], c[i+2]`. However, the scalar code uses only `c[i-1]` (a single element) for the recurrence `a[i] = t + c[i-1]`. Loading a full vector from `c[i-1]` introduces values from `c[i], c[i+1], c[i+2]` that are not yet computed (they depend on the current iteration), breaking the loop-carried dependency.

- **Fix**: The vectorized main loop must handle the recurrence differently. Either:
  - Use a scalar load for `c[i-1]` and broadcast it, or
  - Restructure the loop to compute `a[i]` using the *previously computed* `c[i-1]` from the prior iteration (e.g., keep a scalar `c_prev` variable updated across iterations), or
  - Peel the first vector iteration to compute `c[0..3]` fully before entering the vector loop, then use `c[i-1]` from the already-computed vector.

- **The mismatch at index 1** confirms this: the vector load of `c[i-1]` when `i=4` reads `c[3]` (correct, already computed) but also `c[4], c[5], c[6]` (not yet computed), corrupting the computation for `a[4]`.
