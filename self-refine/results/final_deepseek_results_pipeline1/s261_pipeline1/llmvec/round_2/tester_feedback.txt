The vectorizer candidate has a correctness bug in the vectorized main loop.

- **Incorrect vector alignment for `c[i-1]`**: The scalar prologue runs for `i = 1,2,3`, so `c[3]` is the last element written by the scalar loop. The vector loop loads `c[i-1]` as a full 4-element vector starting at `c[i-1]`. When `i=4`, this loads `c[3],c[4],c[5],c[6]`. But `c[3]` was already updated in the scalar loop, and the vector loop uses it as `vc_prev` for the first vector iteration — this is correct. However, the vector loop also loads `vc = *(float32_t*)(c + i)` which for `i=4` loads `c[4],c[5],c[6],c[7]`. The problem is that `c[4]` and `c[5]` are **not yet computed** by the scalar prologue (only `c[1],c[2],c[3]` were). The vector loop uses `vc` to compute `t3 = vc * vd`, but `c[4],c[5]` contain stale/undefined values.

- **Fix**: The vector loop must load `vc` from the **previous iteration's computed values**, not from the original array. Since the recurrence `c[i] = c[i] * d[i]` is independent per element, the vector loop should compute `c[i]` using the **current** `c[i]` value (which for `i>=4` was never set by the scalar prologue). The scalar prologue must compute `c[0],c[1],c[2],c[3]` fully, then the vector loop should start at `i=4` and load `c[i]` from the array (which now has correct values for indices 0-3). But the mismatch at index 5 suggests the vector loop is using wrong `c` values.

- **Specific fix**: Ensure the scalar prologue computes `c[0]` through `c[3]` (i.e., start `i=0` in scalar prologue, not `i=1`). Then the vector loop at `i=4` will load correct `c[4..7]` from the original array (which are still unmodified). Alternatively, restructure to compute `c[i]` in the vector loop using the loaded `vc` (which is the original value) — this is correct because `c[i]` only depends on itself and `d[i]`. The mismatch at index 5 indicates the vector loop's `c[i]` computation is using a wrong value, likely because the scalar prologue didn't compute `c[0]` and the vector loop's `c[i-1]` load includes `c[3]` which is correct, but `c[i]` load includes `c[4]` which is stale.

- **Recommended fix**: Change scalar prologue to start at `i=0` and run until `i < 4 && i < LEN_1D`. This ensures `c[0],c[1],c[2],c[3]` are all computed. Then the vector loop at `i=4` loads `c[4..7]` (original values) and computes them correctly. The tail loop handles remaining elements.
